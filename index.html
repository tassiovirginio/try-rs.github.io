Instant workspace manager for temporary experiments

Your experiments
deserve a place.

A lightning-fast TUI to manage temporary projects. Create, explore, and clone repositories instantly without cluttering your system.

cargo install try-rs
Get Started
tassiovirginio@rust-box: ~/projects/try-rs

CLI Commands

You can also bypass the UI and use direct commands:

Command Description
try-rs Opens the TUI interface.
try-rs <name> Create (or jump to) a named experiment.
try-rs <url> Clones a repository into a dated folder.
try-rs <url> <name> Clones a repository into a specific custom folder name.
try-rs -s <url> Shallow clone (depth 1) for fast experiments.
try-rs -w <name> Create a git worktree from current repository.
try-rs --setup <shell> Setup shell integration (fish, zsh, bash, power-shell, nu-shell).
try-rs --version Show application version.
try-rs --help Show help message.

Core Features

Built to handle everything from quick tests to deep dives into existing code.

Instant Workspaces

Generate isolated environments in milliseconds. No more cluttering your home directory with manual folders.

Advanced Git Support

Automatic repository cloning and git worktree creation. Switch branches without messing up your main repository.

Fuzzy & Filter

Find past experiments instantly with built-in fuzzy searching and real-time filtering in the TUI.

One-Key IDE Launch

Jump directly into your favorite editor (VSCode, Neovim, Helix) within the workspace using simple shortcuts.

Smart Cleanup

Delete obsolete projects safely. Features an interactive deletion popup to prevent data loss.

Modern TUI

A beautiful Ratatui-powered terminal interface. Browse your experiments with zero latency and full visual feedback.

Configuration

Customize your experience by creating a config.toml file. Supports full color customization and default editor settings.

Linux
~/.config/try-rs/config.toml
macOS
~/Library/Application Support/try-rs/config.toml
Windows
%AppData%\try-rs\config.toml

Environment Variables

TRY_PATH

Overrides the base path where experiments are stored.

TRY_CONFIG_DIR

Overrides the default configuration directory location.

TRY_CONFIG

Overrides the configuration filename (default: config.toml).
